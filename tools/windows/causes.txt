# tools/windows/causes.txt -- why a case does not behave the same on Windows.
#
# `<glob> <cause>` per line, first match wins. The globs are matched against
# the `why` half of a DIFF line from tools/windows/run.sh. The point of this
# file is that the round can say WHY something does not work rather than
# only how much -- a bare success rate would say much less.
#
# The two causes that are left after round WINDOWS are both about a SECOND
# THREAD OF CONTROL: `clone(2)` and `fork(2)`/`execve(2)`/`wait4(2)`. Both
# have Win32 counterparts (`CreateThread`, `CreateProcessW`) whose shape is
# different enough that faking them behind the Linux numbers would be a lie;
# both are open roadmap points.
*860_thread*	THREADS: clone(2) answers ENOSYS -- CreateThread has another shape
*861_thread*	THREADS: clone(2) answers ENOSYS -- CreateThread has another shape
*862_thread*	THREADS: clone(2) answers ENOSYS -- CreateThread has another shape
*1600_net_echo*	THREADS: the case starts a server thread; the sockets themselves work
*2091_dns_loopback*	THREADS: the case starts two server threads; the resolver itself runs on Windows (tools/dns/run.sh builds dns_main for Windows and runs it under Wine)
*834_arc_thread*	THREADS: clone(2) answers ENOSYS -- CreateThread has another shape
*700_process_start*	PROCESSES: fork/execve/wait4 answer ENOSYS -- CreateProcessW has another shape
*"windows build failed"*	BUILD: the Windows build did not come out
*"unknown Win32 function"*	EXTERN-UNKNOWN: an extern fn that is not a Win32 function this compiler knows
*"undefined reference"*	LINK-UNDEFINED: a symbol the PE link cannot resolve
*"exit code"*	EXIT: the exit codes differ
*"output linux"*	OUTPUT: the printed text differs
*1662_std_dir*	LINUX-ONLY: the case lists /proc/self/fd, which only Linux has; std.dir itself works (tools/windows/run.sh, 1910/1919/1921)
*1910_std_fs*	WINE-STUB: Wine 8 CreateSymbolicLinkW is a stub (reports success, creates no link); every other part of the case passes under Wine
*2062_std_process*	LINUX-ONLY: the case drives sh, cat and head; the portable twin is 2064 (identical on both)
*2063_std_process_live*	LINUX-ONLY: the case counts /proc/self/fd and uses sh; the portable twin is 2064
*2065_std_pool*	THREADS: the pool needs clone(2); on Windows the pool runs jobs inline (tests/2066 is the portable twin)
