# tools/liveb4/minquota.txt -- the regression limits of round B4.
#
# Each line is a floor, not a target: the acceptance run fails when the
# number falls BELOW it. They are set a little under what round B4
# measured, so that noise does not break the build and a real regression
# does.
#
# Whoever raises a number here has to say in the commit what made it
# better. Whoever LOWERS one has to say what was given up, and that is the
# whole point of the file: a quota that can be quietly re-frozen measures
# nothing at all.

# The official Web Platform Tests, dom/ area, through the ORIGINAL
# testharness.js. Subtests that the harness reported as PASS.
wpt_subtests 380

# Files in which EVERY subtest passed. A file counts only if its harness
# really finished and produced at least one subtest -- see tools/liveb4/wpt.py.
wpt_whole 15

# The own cases (tools/liveb4/cases.py): script order, the three event
# phases, timers, innerHTML in a fragment context, wrapper identity.
own_cases 14

# The HTTP rules checked against Python's http.server
# (tools/liveb4/http_check.py), six of them counter-checks.
http_rules 28

# How many times less style work a narrowed update does than a full one,
# over the same 30 mutations. Round B4 measured 103; the floor is set at
# 20 because the document the number is measured on may grow.
narrow_factor 20
