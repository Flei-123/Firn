# Vanilla comparison -- method + first laptop result (23.10.2026, HOLO-LAPTOP-3)

Rule: nothing runs on FLEI-ONE without an answer to the `project_needs` question. No Mojang files are copied or read;
Vanilla is only started as a measured object. Until numbers exist, nobody may claim "faster than Vanilla".

## Same conditions
| item | value |
|---|---|
| machine | FLEI-ONE, same power plan, nothing else running, same monitor mode |
| world | same seed + same spawn area (flat copy of tools/mc/view/fixture/world.mcw is NOT Vanilla-loadable: use a fresh world with a fixed seed, note it) |
| view distance | 8 / 16 / 32 chunks (render distance in options), simulation distance = same |
| resolution | 1280x720 windowed (the CPU harness uses 640x360: report both, never mix) |
| camera path | Vanilla: fixed spawn, hold forward + same yaw sweep for 60 s (or /tp loop by command blocks); harness: deterministic flight (docs/MC-PERF.md 1.) |
| runs | 3 per view distance, discard the first 10 s (shader/chunk warm-up) |

## Vanilla frame times
1. Start PresentMon (`PresentMon.exe -process_name javaw.exe -output_file vanilla_r<R>_<n>.csv -timed 60 -terminate_after_timed`).
2. CSV column `msBetweenPresents` -> p50 / p95 / p99 / 1 % low, same definitions as docs/MC-PERF.md (numpy linear percentile, 1 % low = mean of slowest 1 %).
3. Alternative without PresentMon: the game's own debug screen (F3) is NOT precise enough -- do not use for the table.

## Voxel client harness on the same PC
`bash tools/mc/perf/build_win.sh <dir>` builds `bench.exe` (CPU raster, single thread; cross build + wine smoke test pass on the server).
Run `bench.exe world.mcw <radius> 100 10 > out.txt` 3x per radius. Windows GL path: not built yet (no bench_gl) -> only the CPU raster can be compared,
which is NOT a fair comparison against Vanilla's GPU renderer. Mark every table "CPU raster, no GPU" until bench_gl exists.

## Report
Table per view distance: Vanilla p50/p95/p99/1 % low vs Voxel (CPU / GL), tris per frame, RSS, plus hardware line (CPU, GPU, RAM, driver).

## First measurement: Surface Laptop 4 (HOLO-LAPTOP-3), 23.10.2026
Machine: i7-1185G7 (4C), Iris Xe (driver 32.0.101.7085), 16 GB, Win 10.0.26300, AC power, plan "Balanced" (max processor state reads 60 %, left untouched, same for both clients).
Background: Firefox (19 processes), Teams, WebView2 stayed open (not closed on purpose); every run had the same background. Timer resolution at the end: 1 ms.
Scripts: `tools/mc/perf/laptop/mcvan_run.ps1` (server | vanilla | mcplay), `mcvan_stats.ps1`, `mcvan_batch.ps1`. Work dir `%TEMP%\mcvan`, removed afterwards. No accounts or tokens (offline server, `--accessToken 0`).

Method (identical for both clients)
- Server: Vanilla 1.20.1 jar run locally on the laptop, `online-mode=false`, seed 4242, view-distance 16, simulation-distance 4, creative, peaceful, `spawnRadius 0`, `randomTickSpeed 0`, no day cycle. World pre-generated by one warm-up Vanilla run at r16. Transfer jar: `public/<random>` + `curl.exe`, SHA256 checked, file removed from `public/` at once.
- Client view distance 8 and 16 (Vanilla `renderDistance`, mcplay `MCPLAY_VIEW`), window 1280x720 (client area checked: 1280x720 for both), topmost window.
- Vanilla: `javaw` 17, own `--gameDir` (the real `.minecraft/options.txt` is untouched), vsync off, maxFps unlimited, fancy graphics (defaults), sound off, classpath from `1.20.1.json`.
- mcplay: installed Voxel Client, `MCPLAY_GL=1 MCPLAY_VSYNC=0 MCPLAY_FPS=0` (uncapped), `MCPLAY_SOUNDS=0`; GL on Iris Xe confirmed by the log (`gl renderer=Intel(R) Iris(R) Xe Graphics api=wgl vsync=0`).
- Camera: stand at spawn, 30 s settle after join, then one full yaw turn in 45 s (rcon `tp @a ~ ~ ~ <yaw> 8` every 50 ms).
- Frame times: PresentMon 2.6.0 (not elevated, `--process_id`), column `MsBetweenPresents`, first 10 s dropped -> 35 s analysed, numpy-linear percentiles, 1 % low = mean of the slowest 1 %. Present mode for both: "Composed: Copy with GPU GDI" (windowed).
- 3 runs per radius and client, interleaved (V1 M1 V2 M2 ...).

Reading (facts only)
- At 1280x720 on this laptop Vanilla is faster than mcplay GL in all 6 pairs (r8 ~3.9x at the median p50, r16 ~3.5x). **No "faster than Vanilla" claim is possible; the opposite holds today.**
- mcplay r8 is bimodal: two runs at 15.6 ms (= mcplay's own `frame_stats` p50 15.6 ms), one at 7.5 ms (own p50 7.1 ms). Cause NOT investigated (system timer was 1 ms; not a cap: `MCPLAY_FPS=0`, vsync 0). Earlier bench_gl at 640x360 r8 gave 8.7 ms (different harness, 4x fewer pixels, no network).
- Not compared: sound (off for both), CPU/RAM use, Vanilla "Fast" graphics, GPU utilisation, mcplay Vulkan, load time. Only one machine, one world position (spawn), one 35 s window per run.
- Vanilla `MsBetweenPresents` p95 = 10.00 ms in all three r8 runs (same value to two decimals) -- looks like a quantised stall pattern; not examined.
