# Bluetooth host stack (lib/bluetooth)

Platform neutral Bluetooth LE host core in Firn, no C/C++/Rust. All modules are prefixed `bt_` (single module namespace).

## Layers
- `bt_le` little endian reader/writer helpers, `NONE` (usize max).
- `bt_hex` hex dump/parse for traces and tests.
- `bt_uuid` 128 bit UUIDs (16 bit expand to the base UUID), parse/format.
- `bt_hci` H4 command builders (reset, event masks, LE advertising, scanning, connection, encryption, data length).
- `bt_hci_evt` event parser: command complete/status, disconnection, LE connection, advertising reports, connection update, LTK request, completed packets.
- `bt_acl` ACL framing, L2CAP fragmentation and reassembly.
- `bt_l2cap` LE signalling (parameter update, LE credit based connection, flow control credit).
- `bt_att` ATT PDU builders and error codes.
- `bt_gatt_db` attribute database (services, characteristics, descriptors, CCCD, permissions).
- `bt_gatt_server` ATT server (MTU, find info, find by type value, read by type/group, read, blob, write, prepare/execute, notify/indicate).
- `bt_gatt_client` service/characteristic/descriptor discovery state machine.

- `bt_aes` security function e + byte order helpers, `bt_cmac` AES-CMAC (RFC 4493).
- `bt_smp_crypto` ah, c1, s1, f4, f5, f6, g2, h6, h7 (over-the-air little endian, same convention as bumble.crypto).
- `bt_smp_ecdh` P-256 key pair, DHKey, public key validation (little endian coordinates).
- `bt_smp` SMP PDU builders/parsers, reason codes, IO capabilities, auth/key distribution flags.
- `bt_smp_pair` pairing state machine, initiator and responder, Just Works: legacy (c1/s1 STK) and Secure Connections (f4/f5/f6 LTK), key distribution (LTK/EDIV/Rand, IRK, address, CSRK). Random source is a function pointer (`std.crypto.random.random_bytes`).
- `bt_ad` advertising data: build, walk, find (flags, names, UUIDs, TX power, appearance, manufacturer, service data, connection interval range).
- `bt_h4` H4 stream deframer. `bt_transport` function-table interface (send/recv/close).
- `bt_transport_linux` HCI_CHANNEL_USER raw socket (AF_BLUETOOTH/BTPROTO_HCI via syscall, device must be down, needs CAP_NET_ADMIN) and serial UART H4 (termios via ioctl, optional RTS/CTS). Not run against real hardware.
- `bt_transport_stub` Windows and Android: interface only, always `TR_ERR_UNSUPPORTED`. Windows needs a WinUSB/bthusb driver path, Android has no raw HCI for apps (Java API bridge needed). Not implemented.
- `bt_fake_controller` in-memory LE controller (reset, info, buffer sizes, scan with simulated advertisers, create connection, disconnect, ACL loopback) that records an HCI trace (`bt_trace`: `> hex` host to controller, `< hex` controller to host).

## Tests
- `tests/5340_bt_hci_vs_bumble.fi` HCI commands/events against bumble 0.0.236 (generated by `tools/bluetooth/gen_hci_test.py`).
- `tests/5341_bt_att_l2cap_acl_vs_bumble.fi` ATT/L2CAP/ACL against bumble (`tools/bluetooth/gen_att_test.py`).
- `tests/5202_bt_gatt_end_to_end.fi` GATT client discovery against the server, in memory.

- `tests/5360_bt_smp_crypto_vs_bumble.fi` AES-CMAC and all SMP functions against bumble.crypto (`tools/bluetooth/gen_smp_crypto_test.py`).
- `tests/5361_bt_smp_pdu_vs_bumble.fi` SMP PDUs against bumble.smp (`gen_smp_pdu_test.py`).
- `tests/5362_bt_smp_ecdh.fi` ECDH against python cryptography (`gen_smp_ecdh_test.py`).
- `tests/5363_bt_smp_pairing.fi` both roles in memory, legacy and SC, key distribution, tampering, out-of-order PDUs.
- `tests/5364_bt_ad_vs_bumble.fi` advertising data against bumble (`gen_ad_test.py`).
- `tests/5365_bt_h4_fake_controller.fi` H4 deframer, fake controller, transport error paths.

Regenerate with a venv that has `bumble` installed: `python -I tools/bluetooth/gen_hci_test.py tests/5340_bt_hci_vs_bumble.fi`.
