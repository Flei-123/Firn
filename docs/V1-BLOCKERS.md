# Open questions before Firn 1.0

Found while writing `docs/STABILITY.md`. Each item is a roadmap point (group "v1.0-Stabilitaet"). Fixing later is compatible only if marked (C); (B) means it breaks programs and must be settled before the freeze.

| # | Question | Why it blocks | Kind | Status |
|---|---|---|---|---|
| 1 | **Reference implementation**: `SPEC.md` and the code diverge (section 10.5 still lists WASM/aarch64 as postponed; v0.x text). Which one decides? | A promise needs one normative text. Today the frozen corpus is the only authority. | B | **done (20.11.)** Rule: the frozen corpus decides, SPEC follows (`SPEC.md` normative-status note). Divergences found and fixed in SPEC: 10.5 (aarch64 and WASM backends exist), 15.6/15.7 (package manifest exists), 6.3 (no generic enums), 7 (`atomic[T]`, `#[sendable]`, `Io` are planned, the real surface is `thread_*` + `__atomic_add` + `lib/chan`). Still open outside the blocker scope: section 14 addenda are history, not rules. |
| 2 | **Overflow and `release-fast` semantics**: checked levels panic, `release-fast` wraps. Is wrap defined or unspecified? | Programs relying on either behave differently per level. Decide and document in SPEC 13. | B | **done (20.11.)** Already specified in SPEC 13 (`L9`) and `docs/SAFETY.md`: checked levels (`dev`, `dev-fast`, `release-safe`) panic with exit 101, `release-fast` wraps and is DEFINED, never undefined; explicit `+% -% *%` and `+| -| *|` behave the same in every level. Pinned in all four levels by `tests/stable/levels/ovf_*` (10 programs, runner section "level semantics"). Programs must not rely on either side (STABILITY.md). |
| 3 | **`Option[T]` is a struct** because there are no generic enums (`lib/std/option.fi`). Will generic enums come? | Changing `Option` to an enum breaks every user. | B | **done (20.11.)** Decision: `Option[T]` stays a struct `{ has: bool, val: T }` for good; generic enums are still rejected by both compilers. If they arrive, `Option` is not changed and an enum-based type gets a new name. Pinned by `tests/stable/t3_generics_option_struct` and the frozen API list. SPEC 6.3 says so. |
| 4 | **Unary `*` vs `as` precedence** (`*p as u64` parses as `*(p as u64)`), negative literals needing `0 - 1`, statics limited to number/byte-array literals, `&x as u64` rejected. | Surprising grammar quirks must be fixed (or declared final) before the grammar freezes. Needs verification against SPEC 12. | B | **done (20.11.)** Verified with probes: `as` is postfix (SPEC EBNF) so `*p as u64` is `*(p as u64)` and `&x as u64` is rejected; negative literals work everywhere (the `0 - 1` workaround is obsolete); statics accept number expressions, number arrays, byte strings and struct literals, not `str`. Decision: all stay as they are (changing the `as` precedence silently changes accepted programs). SPEC 12.11 lists them, 3 goldens + 5 rejects pin them. |
| 5 | **`std.rt` surface** is imported by 729 tests but is runtime internals. Split into a stable part and an internal part. | Otherwise the core list cannot include it and corpus programs depend on an unstable module. | B | **done (20.11.)** `std.rt` stays one module (no renames, 729 tests keep working). The stable part is the allow-list `tools/stability/rt_stable.txt` (39 names: `Buf`/`buf_*`, `heap_alloc/free`, `mem_*`, `ld*/st*`, `addr_of/ptr_of`, file and stdin helpers, `finish`, `arg_*`); it is frozen in `api_std.txt` like the core modules. Everything else exported by `std.rt` (`run`, `run3`, `spawn`, `wait_pid`, `unlink_file`, `env_value`, `heap_debug_enable`, `buf_grow`, `buf_reserve_or_die`, `dec_small`) is internal and may change. |
| 6 | **Module names are global** (`Modulnamen global eindeutig`). Package-qualified names? | Package ecosystem cannot grow without clashes; changing import resolution later breaks code. | B | open |
| 7 | **Package management** (SPEC 15.6): manifest, lock file and local `needs` exist; registry, version resolution rules and per-package editions do not. | Edition of dependencies is ignored today; manifest keys must be final. | B | open |
| 8 | **SIMD surface** (SPEC 15.4): intrinsics or vector types? | Intrinsics stay experimental until decided. | C | open |
| 9 | **Conditional moves** (SPEC 15.5): rejected conservatively. | Loosening is compatible; document the rule. | C | open |
| 10 | **Coroutine stack size** and growth (SPEC 15.2). | Affects `Io` async behavior limits, not syntax. | C | open |
| 11 | **GC: conservative, non-moving** (SPEC 15.1). Promise "objects never move"? | Needed for FFI pointers; precise scanning would be an internal change. | B | open |
| 12 | **12 open non-guarantees** in `docs/SAFETY.md`. Fix or declare permanent each one. | The safety claim "fast and secure" must say exactly what is not covered. | B | open |
| 13 | **Two compilers** (`firnc0` Rust, `firnc1` Firn). `tools/diff_c0c1.sh` must stay at 0 differences; firnc1 needs the same stable flags. | Stable behavior must not depend on which compiler built the program. | C | open |
| 14 | **ABI** (`L13`): the calling convention for Firn-to-Firn and `#[export_c]` is stable only on x86-64 and aarch64 Linux; Windows and kernel profiles are not listed. | Stable targets list in STABILITY.md. | C | open |
| 15 | **Name**: rename Firn to Fission is not approved. Keep the manifest file and CLI names as they are (`brand_compat`). | Renaming after 1.0 breaks every project. | B | open |
| 16 | **Diagnostics**: error text is unstable by design; tools (LSP, editors) need a machine-readable code per error. | Without error codes tools parse text. | C | open |
| 17 | **Edition differences list** does not exist yet: only `2026` is defined. The first change that needs a second edition starts the list. | Mechanism is in place (`--edition`, manifest key), content is empty. | C | open |
| 18 | **`unsafe fn` in the std core**: N16 marked `std.math.frexp/ldexp` as `unsafe fn`; the API gate flagged it as a signature change. Is `unsafe` part of the stable signature? Callers break under `--unsafe=error`. | Decide before the std core list is final; the frozen list was refreshed once for this (pre-1.0). | B | open |
| 19 | **Concurrency surface**: SPEC 7 promises `atomic[T]`, `#[sendable]`, `Io`; the compiler offers `thread_start(kind, arg)`, `thread_wait`, `thread_lock`, `__atomic_add` and the `__thread_work` dispatcher. Which names are the stable surface? | The goldens now pin the low-level primitives; renaming them later breaks programs. | B | open (found 20.11.); pinned today by `tests/stable/t3_threads_atomic_lock` |
