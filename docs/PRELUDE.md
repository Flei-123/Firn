# Prelude

A few C#-style conveniences work without `import`. The prelude is a source-level
pass in both compilers (`compiler/src/prelude.rs`, `lib/firnc1/prelude.fi`); it runs
per file right after `derive` and before the lexer.

## What is implicit

| You write | The compiler adds |
|---|---|
| `x.to_str()` | module `std.tostr` is loaded (methods on numbers and `bool`) |
| `parse.to_i32(s) catch 0` | `import std.parse` |
| `format.format2(..)` | `import std.format` |
| `chars.count(s)` | `import std.chars` |
| `format("{0} and {1}", x, y)` | `import std.format`, `import std.io`, each argument after the template goes through a file-local generic `__fmt_show[T]` (f-string formatting, so numbers, `bool`, `str` work directly) and the call becomes `format.format2(..)`; up to 8 arguments |
| `println(s)` / `print(s)` | `import std.io` and a file-local `fn println(s: str)` / `fn print(s: str)` |
| `readln()` | `import std.io` and a file-local `fn readln() -> str` (`io.read_line()`: one line without the line break, empty at end of input) |

## Every std module

`name.member` loads `std.name` for every module in `lib/std` (`io`, `time`, `math`, `fs`, `json`, `process`, ...).
The list is generated by `tools/stdimport/gen.sh` into `compiler/src/std_modules.rs` and
`lib/firnc1/std_modules.fi`; a cargo test fails when `lib/std` and the list drift apart. The pass is
`compiler/src/stdimport.rs` / `lib/firnc1/stdimport.fi`, runs after the prelude pass and uses the same
rule: the name is added only if every occurrence in the file is `name.member` (inside f-string
`{..}` too), the file does not import a module of that name, and it declares no `fn name`. A local,
parameter, field or struct-literal key called `time` keeps the file untouched. Interpolation
fragments are lexed without any source pass. `--no-prelude` and `profile kernel` switch it off.

## f-string as str

`f"..."` is a `Fmt` builder. Where a `str` is expected (annotated `let`, function or method
argument, `return`, struct field, assignment, `+`, `==`, `!=`) the compiler wraps it in
`io.fmt_string(..)`. Where a `Fmt` is expected nothing changes. Code in `compiler/src/fmtstr.rs`
(called from the lambda pass `want`) and `lib/firnc1/fmtstr.fi` (called from `sema.fi expr`).

## Methods on values

`std.strmethods` and `std.nummethods` hold the everyday C# methods as `impl` blocks on `str` (through
the view struct `StrMethods`) and on `i32`, `i64`, `usize`, `f64`. The loader adds the module
(`modules.rs resolve`, `bin/firnc1.fi implicit_import`) when a user file (not a file below `$FIRNLIB`)
contains `.name(` for a name in the generated table (`compiler/src/method_modules.rs`,
`lib/firnc1/method_modules.fi`, written by `tools/methodmods/gen.sh` from the `fn name(self` lines of
the two modules). A new method in one of these modules needs `sh tools/methodmods/gen.sh`.

| You write | Result |
|---|---|
| `s.to_upper()`, `s.to_lower()`, `s.replace(a, b)` | new `str` |
| `s.split(sep)`, `s.split_whitespace()` | `Vec[str]` |
| `sep.join(parts)` | `str` (parts is a `Vec[str]`) |
| `s.substring(start, count)` | byte offsets, clamped, no copy |
| `s.index_of(part)`, `s.last_index_of(part)` | `i64`, -1 when missing |
| `s.pad_left(w)`, `s.pad_right(w, fill)` | fill is a `u8`, default space |
| `s.repeat(n)`, `s.char_count()` | `char_count` counts code points, `length()` counts bytes |
| `s.trim()`, `s.contains(p)`, `s.starts_with(p)`, `s.ends_with(p)`, `s.is_empty()` | from `std.str` |
| `x.abs()`, `x.min(y)`, `x.max(y)`, `x.clamp(lo, hi)`, `x.pow(n)` | numbers |
| `x.sqrt()`, `x.sin()`, `x.cos()`, `x.floor()`, `x.ceil()`, `x.round()`, `x.to_int()` | `f64` |

Method resolution on a string tries `str__name`, then the string views (`str.Span`, `StrMethods`). A
function of the module `str` whose first parameter is a pointer to another struct (`replace(out:
*mut Bytes, ..)`) does not count as a method of a string, so `s.replace(a, b)` reaches the view method.
A `Span` (result of `trim()`) reaches the same views. `impl str { .. }` in an imported module works in
both compilers (the method keeps the name `str__name`, like `impl i64`).

`--no-prelude` and `profile kernel` switch the loading off; `import std.strmethods` always works. A program
that defines its own `impl i32 { fn abs(*self) }` while using `x.abs()` somewhere must not trigger the
module (rename its method) -- the loader does not look for that.

## Rules

* Loaded only when used. A file that does not use these names is not touched and
  compiles to the same assembly as before.
* Your own name wins. A module name is added only if every occurrence of the name in the
  file is `name.member` (no `let parse`, no field `format:`, no `fn chars`), and the file does
  not import it. `println`/`print` are added only if every occurrence is a call and the file
  declares no function of that name. `to_str` is loaded only if no file of the program
  declares a `to_str` method (`fn to_str(*self ..)`) and none imports `std.tostr`.
* `--no-prelude` switches the pass off.
* Files with `profile kernel` are never touched, so `--no-gc`, kernel and freestanding
  builds see no change.
* Imports are inserted in front of line 1 on the same line, wrappers are appended after the
  last line: line numbers never move.

## Variadic `format`

`format(tpl, a, b, c)` is the typed variadic form for the common case: any number
(0 to 8) of arguments of any type that an f-string can print. It is a source rewrite
inside the prelude. The general `..T` parameter is a separate feature
(`docs/VARIADIC.md`); `format` stays as it is because its arguments have mixed types.
Nested calls work (`format("{0}", format("<{0}>", x))`). More than 8 arguments are left
untouched and fail as an unknown function. `format.format0` to `format.format8` stay available.

## gc_init

The compiler already writes the call to `gc_init()` into the generated start code
(x86-64, aarch64, Windows, WASM) whenever the collector runtime is linked in. An explicit
`gc_init()` stays valid (idempotent). Proof: `tests/6823_gc_init_automatic.fi`,
`tests/6824_gc_init_explicit_still_valid.fi`.

## C#-style aliases

snake_case stays the standard. In addition a PascalCase call is renamed to the existing snake_case
name, so `x.ToString()`, `list.Add(1)`, `s.Trim().Split(" ")`, `Println(..)`, `ReadLine()` work.
The pass is a source rewrite in both compilers (`compiler/src/csalias.rs`, `lib/firnc1/csalias.fi`),
it runs first after `derive`, and its table is generated: `tools/csalias/table.txt` (explicit
entries) plus the PascalCase form of every name in `method_modules.rs`, written by
`sh tools/csalias/gen.sh` into `compiler/src/csalias_table.rs` and `lib/firnc1/csalias_table.fi`.
A replacement shorter than the name is padded with spaces, so columns of later tokens stay.

| Form | Rule |
|---|---|
| `x.Name(..)` | method or module function, becomes `x.snake(..)` |
| `Name(..)` | only for table entries marked `bare`: `Println`, `Print`, `ReadLine` (`io.read_line`), `Sleep` (`time.sleep_ms`), `Millis` (`time.millis`) |
| `x.Length`, `x.Count` | property form, becomes `x.length()` (string) and `x.len()` (Vec/Map/Set); `x.Count()` also works |

Aliases: `ToString`=`to_str`, `Add`/`Push`=`push`, `Pop`, `Insert`, `Clear`, `Sort`, `Reverse`, `Extend`,
`RemoveAt`=`remove_at`, `IndexOf`=`index_of`, `IsEmpty`=`is_empty`, `Contains`, `Substring`, `Trim`,
`TrimStart`=`trim_left`, `TrimEnd`=`trim_right`, `Split`, `Replace`, `Join`, `ToUpper`=`to_upper`,
`ToLower`=`to_lower`, `StartsWith`=`starts_with`, `EndsWith`=`ends_with`, `Parse`=`parse`,
`TryParse`=`try_parse`, `Keys`, `Values`, `GetOr`=`get_or`, `ReadAllText`=`read_text`,
`WriteAllText`=`write_text`, `AppendAllText`=`append_text`, and every PascalCase form of a method of
`std.strmethods`/`std.nummethods` (`Sqrt`, `Abs`, `Min`, `Max`, `Pow`, `Floor`, ...).

Rules:

* Your own name wins. A table name is left alone in the whole file when the file declares it
  (`fn Add`, `impl .. { fn Add(..) }`) or uses it any other way (field `Count: i32`, variant `Add(i32)`,
  variable). A call behind a type path (`Op.Add(..)`) is never renamed.
* The decision is per file. A PascalCase method defined in another file and called here is renamed
  and then fails as an unknown method; call it through a name that is not in the table.
* An unknown PascalCase name keeps its spelling in the error. `did you mean` also tries the
  snake_case form of a PascalCase name (`DoubleIt` suggests `double_it`).
* Implicit module loading (`to_str`, `strmethods`, `nummethods`) sees the renamed code.
* Not covered: static C# receivers (`Console.WriteLine`, `Math.Sqrt`, `File.ReadAllText`), `Set.Add`
  (the Set method is `add`), `int.Parse`.
* `--no-prelude` and `profile kernel` switch it off.
