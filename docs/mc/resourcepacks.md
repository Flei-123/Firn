# Resource packs (mc_assets)

Answer: **yes, supported.** `lib/mc/mc_assets.fi`, test `tests/2812_mc_assets.fi`, `bash tools/mc/assets/run.sh` (`RESULT mc-assets: ok`).

## Format
ZIP with `pack.mcmeta` (JSON, `{"pack":{"pack_format":N,"description":...}}`) and `assets/minecraft/textures/block/<name>.png`
(also `.../item`, `.../entity`, `models/`, `blockstates/`, `sounds.json` + `sounds/**.ogg`, `lang/` -- later). Only block tiles are read today.

## Clean room / licence
* The PLAYER supplies packs locally at run time (file path / drag-and-drop). Nothing from any pack is committed, bundled or downloaded by us.
* We read no Mojang files and ship none. Tests use packs built in-process from own pixel patterns. Default look = our own `mc_texture` tiles.
* File/path names are a public format convention; the `tile_file` name table contains names only.

## Load flow (implemented)
1. `pack_open_file`/`pack_open_mem` -> ZIP reader (`lib/zip`, bounded, unsafe names refused) -> `pack.mcmeta` must exist and hold a number `pack_format`.
2. `stack_push` in priority order: **first pushed = top, wins** (max 8). Error codes: IO -1, ZIP -2, NO_MCMETA -3, BAD_MCMETA -4, FULL -5; garbage never crashes.
3. `assets_apply(stack, atlas)`: for every default tile with a pack name (ids 1..40) the top-most pack with a decodable PNG wins
   (`lib/paint/png`, limit 4096x4096); otherwise the default tile stays (fallback). A broken PNG in a high pack falls through to the next pack.
4. Hash tiles 41..56, unknown, test: no pack name, always default. With the extended tiles (below) every solid block has pack names; the hash tiles stay for `tex_build_tables`.

## Atlas / tile sizes
* Atlas has ONE tile size (power of two, caller's choice). Each source image is nearest-resampled (first frame, `w x w`) to it.
* Recommended: tile size = max size over the loaded packs (clamped e.g. 64). Default tiles exist at 16 only -> for larger atlas they should be
  upscaled (nearest) when no pack provides a tile (done: `atlas_fill_default` upscales).
* Later: multi-layer texture array (one layer per size class, 16/32/64/...), mipmaps, per-tile avg colour update (`atlas_avg`).

## Client integration (lib/mc/mc_packs.fi, lib/mc/mc_texext.fi)
* **Extended tiles:** `mc_blocktex.fi` (GENERATED by `tools/mcgen/gen_blocktex.py`, union of all flattened versions: 1171 names) maps every block name to
  3 texture slots (side/top/bottom), each a candidate list of pack file names (`stone_stairs` -> `stone`, `oak_slab` -> `oak_planks`, `grass_block` -> `_side/_top/dirt`,
  logs `_top`, sandstone family, quartz, ...; blocks outside the curated `MULTI` set use ONE texture for all faces). Rules are heuristics of the public naming convention,
  verified only with self-built packs -- a wrong guess shows the default tile; fix the rules in the generator, never the output.
  `tex_build_tables_ext` assigns tile ids `64 + i` in registry order (version dependent, NOT pack dependent -> meshes survive a reload). 1.20.1: ~1050 slots at most;
  `texext_atlas_new(ts)` is 32 columns wide (e.g. 1.20.1 at 32 px: ~1024 x 1100; the GL texture array gets one layer per tile, GL needs >= ~1100 layers).
* **Default tiles at any size:** `atlas_fill_default` now draws/upscales (nearest) the 16 px defaults to any power-of-two tile size.
* **Pack list:** `res_add_list("a.zip,b.zip")` (argument), `res_load_config` (`pack=`, `tile=`, `tile_max=`, `auto=`, `mcdir=`, `sounds=`), first = top priority;
  `res_autodiscover` adds `<mcdir>/resourcepacks/*.zip` (name order, lowest priority; Windows `%APPDATA%/.minecraft`, macOS `~/Library/Application Support/minecraft`, else `~/.minecraft`)
  at RUN TIME only. Tile size: config, else biggest of the first block textures, clamped to `tile_max` (64).
* **Hot reload:** `res_reload_upload(m, &backend)` re-reads the files, rebuilds the atlas and calls the backend table `upload_atlas` (CPU raster: pointer swap, GL: new texture array).
* **Animation:** `<tex>.png.mcmeta` `animation` {frametime, frames [n | {index,time}], interpolate} on a vertical strip; frames resampled once; `res_tick(m, tick, &backend)`
  picks the frame per game tick (interpolation = integer blend, deterministic) and re-uploads the whole atlas when something changed (partial upload = later). Strips WITHOUT
  an `animation` object stay static (first frame) -- vanilla behaviour not verified. Square frames only.
* **mcview wiring (13.10., s5):** `--pack=a.zip,b.zip` or env `MC_PACKS` / `MC_PACK_CONFIG` / `MC_PACK_AUTO` (+ `MC_PACK_DIR`, `MC_PACK_TILE`) -> `mc_packs.res_setup_env`; extended tile tables; `MCVIEW_PACK_TICK=n` (animation tick), `MCVIEW_PACK_RELOAD=1` (hot reload between frames). A windowed client calls `res_tick` once per game tick and `res_on_key(m, &backend, RES_KEY_RELOAD)` from its key handler. Offline test: `bash tools/mc/view/run.sh --offline` (fixture packs from `tools/mc/view/mkpack.py`: hash != default, deterministic, reload keeps the image, flag == env, 32 px != 16 px, priority, broken pack warns). Without packs the image is unchanged (python reference hash). Not compared with the python renderer when packs are on.
* **Pack sounds (`lib/mc/mc_packsnd.fi`, test 2895):** `sounds.json` + `sounds/**.ogg` of every pack -> Aulos bank events (`packsnd_apply`, mode from `res_sounds_mode`: synth = nothing, original/both = pack events; vanilla merge: the lists of ALL packs are joined top first, `replace: true` cuts the packs below, same file once, `type: event` entries ignored; `stream` ignored; `volume` / `pitch` are PER ENTRY (engine per-slot factors, bank fields `sample_volume` / `sample_pitch`; event volume stays 1.0; same file twice = the first entry's factors; test 2994); `weight` (1..1000, default 1) = number of the event's <= 16 sample slots the file gets (the engine picks uniformly from the slots; exact while the weights sum to <= 16, above that scaled proportionally, >= 1 slot each; test 2993); <= 1600 files / events and never more than the free room of the engine (2048 samples / events). Hot reload: files are hashed (FNV-1a), unchanged = sample reused, changed = takes over its old sample slot, so the sample table does not leak; test 2895). Animation: partial atlas upload still whole-atlas.
* **Not done yet:** folder packs, mesher/renderer use of the models (below: the bake is done, the game still draws non-cubes as full cubes), partial atlas upload for animation (whole atlas today), `lang`, GUI textures. OGG: decoder exists (`audio.load_ogg`, used by `mc_packsnd`).

## Later
* **Animated textures:** `<tile>.png.mcmeta` (`animation`: frametime, frames, interpolate); strip PNG (height = n * width); needs per-frame atlas upload or layer cycling.
* **Models / blockstates:** JSON models (parents, elements, rotations, UV) -> mesher input; replaces the "hash tile" fallback and handles non-cubes.
* **Sounds:** `sounds=synth|original|both` in `mc_audio`: `synth` = our bank (default), `original` = pack `sounds.json` + OGG (needs Vorbis decoder, not present),
  `both` = pack overrides event by event, synth fills the rest.
* Pack list UI / persistence (order file in the user dir), reload without restart, `.zip` vs folder packs, `lang`, GUI textures (HUD font).

## Effort (rough)
Done: block tiles + priority (this). Size classes/upscale default + format table: 0.5 d. Animation: 1-2 d. Models/blockstates: 4-6 d.
OGG + sound.json + mc_audio modes: 3-4 d. UI + persistence: 1-2 d.

### Pack sounds in mcplay (r165)
* **O key (mcplay):** packs sounds off (synth bank back) <-> on (config `sounds=` / `MC_PACK_SOUNDS`, default both) at runtime; the sample table and the sample id pool do not grow (`engine_event_replace` hands the tail of the pool back); gate `run_packsnd.sh` (4).
* `MC_PACK_SOUNDS=synth|original|both` (env, overrides the config's `sounds=`; needs packs: `MC_PACKS` / `MC_PACK_CONFIG` / `MC_PACK_AUTO`). Default `synth` = nothing changes.
* `both`: synth bank first, then the pack events on top (event by event). `original`: only the pack events (also after the O key: `engine_events_clear` drops the synth events first, samples are reused by hash; run_packsnd.sh run 5); without a single usable pack sound mcplay warns and falls back to the synth bank.
* Start: `audio_start` -> `mc_packsnd.packsnd_apply`. Log line: `mcplay: pack sounds mode=<1|2> events=<n> samples=<engine samples>`.
* **T (hot reload)** re-reads the packs, then rebuilds the pack sounds. With a device sink the audio thread is stopped around the bank load (engine rule) and restarted;
  unchanged OGG = same sample (hash), changed OGG = takes over its old slot -> the `samples=` number stays equal. Pack events that vanished stay (small).
* Test: `tools/mc/play/run_packsnd.sh` (server + Xvfb; both/file with a changed-OGG reload, both/device with PulseAudio null sink, original/file).

## Models / blockstates (r80, lib/mc/mc_model.fi + mc_model_ref.fi, tests 3945 / 3946)
* **Done (library level, CPU only):** `blockstate_select(stack, block, "k=v,k=v", seed, &sel)` picks the models of a block state from `assets/minecraft/blockstates/<block>.json`
  (variants: key = subset of the state in any order, `""`/`normal` = all, weighted lists by seed; multipart: `when` with `a|b`, `true/false`, `OR`, `AND`, `apply` object or weighted list).
  `model_bake` / `blockstate_bake` read `models/<path>.json` (parent chain up to 16, `#texture` references, `elements`, element rotation incl. rescale, face `uv` / `rotation` /
  `cullface` / `tintindex`, `shade`) and append quads to a `Baked` (28 f64 per quad: 4 corners in block units, UV 0..16, texture index, cullface, tint, shade, direction).
  Variant `x` / `y` (multiples of 90, x first) turn quads + cullfaces around the block centre; `uvlock` keeps the texture on the world axes (UV turned back by the quarter turns of the face plane).
* **Own built-in parents** (written from the shapes, no Mojang file): `block/cube`, `cube_all`, `cube_column`, `cube_bottom_top`, `slab`, `slab_top`, `cross`, `stairs` (straight only).
  A pack file with the same name wins. Inner / outer stairs, fences, doors etc. come from the pack's own model files.
* **Reference view:** `mc_model_ref.baked_load_textures` + `ref_render` draw the quads orthographically from one of six directions (nearest, depth, alpha 0 = hole) -- oracle for UV
  orientation, rotation, uvlock; not the game renderer.
* **Unverified against a real client** (no Mojang pack available): corner order, default UV, face rotation direction, variant x (north -> down) / y (north -> east), element rotation sign
  (right handed), uvlock. All are checked for self-consistency in the tests only.
* **Not done:** mesher / renderer integration (texture names -> atlas tiles, 1/16 vertex format, culling against neighbours via `cull`), `builtin/generated` item models, `display`,
  `ambientocclusion`, `overrides`, `!` negation in `when`, `elements` with `light_emission`.

## Models in the mesher (r230 / r231, opt-in, CPU back end)

`lib/mc/mc_model_mesh.fi`: block state id -> `reg_state_text` split into name + `prop=value,...` -> `blockstate_bake` -> quads with atlas tiles
(texture name -> extended tile through its candidate names), cullface against opaque / unknown neighbours, light of the cell in front.
Only states whose model is NOT a unit cube become model states (stairs, slabs, plants ...); they leave the cube mesher (`ms_prepare` zeroes their
tiles and opaque bit). Weighted variants use `seed_from_pos` (4 seeds per state, baked on demand). `'!'` in `when` negates a value list.
Own built-ins: stairs, inner_stairs, outer_stairs. Output = `MQ_WORDS` (24) f64 per quad, drawn by the CPU raster as `MESH_MODEL` meshes
(`mesh_class(MESH_MODEL)` + `mesh_upload`, `raster_draw_models`). `mc_render_world.wr_set_models(wr, &modelset)` switches it on (default off).
NOT done: mcplay switch (MCPLAY_MODELS=1), mc_stream path, GL / VK, biome tint, AO, translucency, reload of the ModelSet after a pack change.
