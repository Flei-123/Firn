# SYNTH -- procedural sound bank (Minecraft client + OrientOS system sounds)

State: 12.10.2026. Libraries `lib/audio/synth_osc.fi`, `synth_fx.fi`, `synth_recipe.fi` (the old CORDIC sine `audio.synth`
is untouched and still bit-identical), generator `tools/sounds/gen`, recipes `tools/sounds/mc.json` (89 sounds, 250 WAVs)
and `tools/sounds/orientos.json` (18 sounds), test `bash tools/sounds/run.sh` -> `RESULT sounds: ok`, unit test
`tests/2796_audio_synth.fi`.

## Decision
Mojang sounds are NOT copied or shipped (clean room, copyright). Standard = this synthesis bank: own IP, tiny (recipes
~240 kB JSON), deterministic (WAV hashes are stable). Optional on top (not here): import of the player's own original assets
at run time (worker mc-p5, never in the repo) and CC0 sounds (only with source + licence per file in the manifest).
The same technique makes the OrientOS system sounds.

## Libraries
* `audio.synth_osc`: signals = f64 arrays (address, length). `osc_fill` (sine, tri, saw, square, pulse; phase accumulating,
  PolyBLEP band limiting for saw/square/pulse, phase modulation input for FM), `noise_fill` (white, pink = Kellet,
  brown), `env_fill` (multi segment envelope, curve per segment: `shape(u, c)`, c=0 linear, c<0 fast start / slow end,
  c>0 slow start), `pluck_fill` (Karplus-Strong), `add_voice` (soft note), `Rng` (xorshift64*), `pow2`, `sin_turn`.
* `audio.synth_fx`: `fx_svf` (TPT state variable) and `fx_biquad` (RBJ) as LP/HP/BP/NOTCH with per-sample cutoff and Q,
  `fx_delay` (echo + feedback), `fx_reverb` (Freeverb: 8 combs + 4 allpasses, mono), `fx_softclip`, `fx_limit`,
  `fx_crush` (bit depth + sample hold), `fx_dcblock`, `fx_normalize`, `fx_fade`, `fx_add`, `fx_shift`, `fx_to_s16`.
* `audio.synth_recipe`: `recipe_render(json, sound, rate, variant, &Sound, &err)` renders one recipe sound.
* Determinism: only `+ - * /` on f64, no libm, no FMA; sine = 4096 point table from the integer CORDIC of `audio.synth`
  (+ linear interpolation, error 3e-7); `pow2` = Taylor series; random numbers integer. Same bits on every platform.

## Recipe format (`synth-recipe-1`)
```
{ "format":"synth-recipe-1", "name":"mc", "rate":44100, "license":"own",
  "buses":[{"name":"master","volume":1.0},{"name":"sfx","parent":"master","volume":0.9}],
  "sounds":[ { "id":"block.stone.step", "duration_ms":176, "seed":1234, "variants":4, "peak_db":-3,
               "fade_in_ms":1, "fade_out_ms":8, "out":"mix", "aliases":["minecraft:..."], "preview":1,
               "event":{"bus":"sfx","volume":1.0,"volume_random":0.1,"pitch_random":0.08,"loop":false},
               "nodes":[ {"id":"n","type":"noise","color":"white"}, ... ] } ] }
```
Nodes run in order; each makes one signal that later nodes name (`"in"`, `"src"`, `"pm"`, or as a parameter).
Types: `osc` (wave, freq, pm, pm_depth, width, phase, scale, offset), `noise` (color), `env` (points [[ms, level, curve]..]),
`adsr` (a, d, s, hold, r, at, peak, ac/dc/rc), `filter` (kind lp|hp|bp|notch, mode svf|biquad, in, cutoff, q), `gain`,
`mul` (in:[ids]), `mix` (in:[id | {src,gain}], gain), `delay`, `reverb`, `clip`, `limit`, `crush`, `shift`, `pluck`,
`notes` (generative pentatonic notes: root, scale, octaves, step_ms, density, attack_ms, decay_ms, h2, h3, gain).
Parameter forms: number | `"node-id"` (that signal, per sample) | `{"rand":[lo,hi]}` | `{"note":midi}` |
`{"sweep":[a,b],"ms":T,"curve":c,"log":true,"unit":"note"}` | `{"src":"id","base":b,"depth":d}` (= b + d * signal).
Variants: variant k seeds with mix(seed, k); each node has its own stream, so `rand` and noise differ per variant, never per run.
After the graph: mean removal, fades, normalisation to `peak_db` (default -3 dBFS), S16 quantisation (round half away).
The JSON files are generated by `python3 tools/sounds/mkrecipes.py` (material / tone templates) and committed; edit either.

## Generator and outputs (for mc-p5 and OrientOS)
```
firnc -o gen tools/sounds/gen/main.fi        (FIRNLIB=lib)
./gen tools/sounds/mc.json <outdir> [--bank bank.json] [--manifest manifest.json] [--preview mc_preview.wav] [--only PREFIX] [--rate N] [--list]
./gen tools/sounds/orientos.json <outdir> --preview os_preview.wav
```
Writes `<outdir>/<id>.wav` (or `<id>_<k>.wav`, k=1..variants), `bank.json` (audio.bank format: buses, events with `samples[]`,
`volume`, `volume_random`, `pitch_random`, `loop`; aliases are extra events with the same samples), `manifest.json`
(`file, event, variant, source "synth:<id>", license, seed, sha256, duration_ms, peak_dbfs, rms_dbfs`).
Load: `bank.bank_load_file(&b, &e, "<outdir>/bank.json")` (samples are found next to the bank file). Engine limits: 512 samples
(the MC set uses 250, OrientOS 18).

## Sets
* **MC** (`mc.json`): `block.<type>.<step|break|place|hit|fall>` for the 13 types of `mc_audio` (stone, wood, gravel, grass, sand,
  snow, glass, wool, metal, deepslate, netherrack, slime_block, bone_block; 2-4 variants each); `ambient.wind`,
  `weather.rain`, `entity.lightning_bolt.thunder`, `block.water.ambient`, `ambient.cave`, `ambient.drip`; UI `ui.button.click`,
  `ui.hover`, `ui.error`; `entity.player.levelup`, `entity.experience_orb.pickup`; rudimentary voices `entity.{zombie,cow,pig,chicken}.{ambient,hurt,death}`;
  music `music.ambient_loop` (32 s, aliases `music.game|creative|menu`). Event names are strings only (names are not files).
  Pitch note: `mc_audio` plays hit at pitch 0.5 and break/place at 0.8, so the hit samples are short and bright.
* **OrientOS** (`orientos.json`): login, logout, lock, unlock, notification, message, error, warning, success, click, hover,
  volume_ping, usb_in, usb_out, mic_on, mic_off, shutdown, boot; 50 ms - 1.95 s; one scale (D major pentatonic), one timbre
  (sine + soft 2nd partial + a little FM shimmer, soft reverb); buses master / ui / sfx. The names are a PROPOSAL: the
  OrientOS tree (`/root/osum-unterbau`) has no sound-event list yet (only `sound.volume` / `sound.mute` in ACTION-BUS).

## Tests
`bash tools/sounds/run.sh` (about 40 s): generates both sets twice (hash must be identical), then per WAV: S16 mono at the
recipe rate, length == duration, peak == `peak_db` (and <= -1 dBFS), no clipped sample, RMS -45..-9 dBFS, DC < 0.2 %, first
and last sample near 0, SHA256 == manifest == `tools/sounds/ref/<set>.sha256`; bank names only existing files and every
sound is an event; independent numpy FFT confirms the pitch of two pure tones; `tools/sounds/bankcheck.fi` loads the bank in
`audio.bank` and plays every sample in `audio.engine` (non-silent). After an intended sound change: `bash tools/sounds/run.sh --update`.
`tests/2796_audio_synth.fi`: pow2/sine/log2 accuracy, oscillator range/mean/fundamental, noise determinism and pink tilt, SVF
pass/stop band gains, envelope, softclip/limiter bounds, crush levels, delay echo, reverb tail, recipe determinism.

## HONEST (limits)
* Sound quality is subjective and was NOT judged by ear here: the levels, spectra and hashes are measured, "does the stone step
  sound like stone" is not. Expect a clearly synthetic, simple character (creature voices are crude formant sketches).
* No Mojang sample is used or imitated sample by sample; the event NAMES follow the game so a resource pack or the optional
  import (mc-p5) can replace the sounds. CC0 sounds are not included (would need source + licence per file).
* Python gold test for the DSP is partial: pitch of tones, levels, hashes, determinism. A bit-exact Python port of the SVF /
  biquad / noise is NOT done (open: tools/sounds/check.py could port `sin_turn`, `pow2`, xorshift64* and compare dumps).
* Reverb tails are cut at the end of the buffer; loops (`ambient.*`, `music.*`) are made loopable by fade in/out, not by
  a seamless crossfade. Music is generative pentatonic notes, not composition.
* Rendering is offline whole-buffer f64 (the 32 s music takes ~2 s); not a real time engine.
