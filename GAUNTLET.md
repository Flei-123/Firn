WAS DU BAUEN SOLLST:

1) THE PANE BOX / SCROLL VIEWPORT (lib/fui/viewport.fi). Today there is a scrollbar WIDGET (wave2.draw_scrollbar), but no container that holds more content than its height. What is needed: a viewport with its own size, content of any size behind it, an offset in both directions, REAL CLIPPING (nothing is painted outside the viewport -- measured, not claimed), scrolling with wheel and keyboard, scrollbars that compute themselves from the viewport/content ratio and only appear when needed, and a smoothly decaying motion (kinetic scrolling via lib/fui/anim.fi, NO second time calculation). Plus `viewport_ensure_visible`, which brings a rectangle into the viewport -- that is the building block without which keyboard operation in a long list does not work. The hit test has to take the offset into account, otherwise you click on the wrong element.

2) THE DESCRIPTION (lib/fui/scene.fi + lib/fui/sheet.fi). This is the core of the job.
   - scene.fi: a TREE of nodes. A node has a kind (box, text, image, SVG, widget from wave2/wave3), an identifier (`id`), any number of CLASSES (like `class=` on the web), children, and a style. The tree is built ONCE and then processed in two passes: MEASURE (every node reports its preferred size through the existing render.pref_of) and ARRANGE (flex.fi or layout.fi distribute the space), and only then DRAW. No node may still change its size while drawing.
   - sheet.fi: a STYLE SHEET. Rules of the form "selector -> style values", with selection by kind, by id, by class and by state (hover/pressed/focus/disabled), plus nesting ("class A inside class B"). Several rules that match the same node are merged by a clear, RE-CALCULATED precedence (like specificity in CSS: id beats class beats kind; at equal rank the rule written later wins), and a child inherits from the parent what is inheritable (font family, size, colour, line height) and only that. Transitions (`transition`) and transformations (`transform`) are perfectly normal style values and go to anim.fi and transform.fi respectively.
   - The style sheet is built IN THE SOURCE (function calls), not parsed from a text file -- a CSS reader would be a second place for something lib/browser can already do, and the tree expressly forbids that.
   - PROOF that it really carries: rewrite ONE existing example from tools/fui/ (e.g. the gallery of the waves or the settings page) with scene+sheet and show that the picture is the same or looks better and that the source gets much shorter. Name the number: lines before, lines after.
