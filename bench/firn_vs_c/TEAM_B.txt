NOTES (Team B)
- All 10 pairs verified: Firn release-fast, release-safe, dev-fast, gcc -O2, gcc -O3 -march=x86-64 print the identical line.
- sha256 checked against Python hashlib (first 8 digest bytes, big-endian): identical.
- No compiler errors, no missing Firn features. `else if`, static mut arrays (incl. initialised u32 tables), u32 rotates/shifts all worked.
- binary_trees: Firn uses the idiomatic GC variant (`gc class Tree`, gc_init, no manual free); C uses malloc/free per node + recursive release.
  rt.heap_alloc is page granular (mmap per block), so it is unusable for 16-byte nodes. This pair measures GC allocation vs malloc/free, not identical allocators.
- memcpy_loops, strbuild, jsonscan: C side has `#pragma GCC optimize("no-tree-loop-distribute-patterns")` so gcc keeps the hand-written loops (checked with objdump for memcpy/memset calls in memcpy_loops: 0).
- strbuild: Firn grows via mmap + word-copy loop + munmap (syscall 11); C via malloc + word-copy loop + free.
- soa_access: Firn AoS uses raw memory with stride 4 words (no struct arrays); C uses a real struct array.
- hashmap: lookup phase 3 hits no key (all 2M misses); checksum = hits-sum * 1000003 + misses.
- Timing (approx., busy host, one run): fnv_hash 0.63 s, sha256 0.15-0.23 s, jsonscan 0.35-0.4 s, strbuild 0.2-0.35 s, memcpy_loops 0.17-0.45 s, binary_trees 0.23 s (C) / 0.6 s (Firn fast), hashmap 0.25-0.33 s, soa_access 0.23-0.33 s, crc32 0.87-1.16 s, wordcount 0.3-0.36 s.
