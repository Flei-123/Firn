# Notes (Team A)
- All 10 pairs: Firn release-fast, release-safe, dev-fast, gcc -O2, gcc -O3 -march=x86-64 print the same line.
- Output: nbody (negative, i64) and floatloop/spectral_norm/fannkuch use print_i64; the rest print_u64.
- Wall times (busy host, load ~20, one run, release-fast / release-safe / gcc-O2 / gcc-O3, seconds):
  primes .53/.18/.48/.56  qsort .27/.32/.24/.23  mandelbrot .24/.25/.25/.26  nbody .95/.97/.62/.58
  fannkuch .34/.42/.29/.27  spectral_norm .22/.25/.16/.15  matmul .40/.50/.31/.35 (N=700)
  fib 1.09/1.10/.24/.22 (fib(40); gcc inlines/unrolls the recursion)  bitops .77/.87/.82/.76  floatloop 1.31/1.27/1.20/1.10
- Compiler problem: indexing through a pointer (`p[i]` with p: *mut f64) is rejected:
  "error: index on the non-array type *mut f64". Workaround: static mut arrays with usize offsets
  (spectral_norm) or *((p as usize + i*8) as *mut f64).
- No other compiler errors. Large static arrays (20 MB u8, 8 MB u32) work. Shifts, rotl via (v<<k)|(v>>(64-k)),
  __sqrt, f64->i64 `as` all fine; no popcount/rotate intrinsic used (SWAR in both languages, fair).
- Design: mandelbrot MAX_ITER 500 and matmul N=700 (instead of 200 / 300) to reach >0.2 s; nbody 4M steps; spectral_norm n=1500.
